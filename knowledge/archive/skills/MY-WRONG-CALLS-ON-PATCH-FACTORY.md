## Evidence mistakes worth keeping

- A manifest fallback assigned the expected package to the observed value and confirmed a foreign APK. A sentinel then rejected valid downloads because real readers had not been tested. Test observed formats and bad inputs, not a convenient invented fixture alone.
- Applying N is selected, not completed. Duplicate Facebook patch names inflated counts and added no coverage. Current gates compare distinct actual/requested names and refuse cross-bundle duplicate requests.
- An SDK37 signer parser assumed legacy labels and rejected every target. Actual stdout revealed V3.0 Signer certificate SHA-256. Fix supported formats, not verification requirements.
- Assuming every .so was ELF rejected Facebook's real ZIP/DEX containers and literal marker files. Inspect content and preserve exact source bytes; DEX remains executable, not harmless data.
- A narrow Facebook filter hid the earlier anonymous GitHub 403. Full logs exposed resolver/build transport divergence. Prime Video metadata said 3.0.452 while the input APK said 3.0.452.257. Resolve once and use exact bytes/metadata.
- Key Mapper's invalid/corrupt latest JAR exposed existence-only cache handling. Failed bytes were unavailable; truncation, error-page and cache poisoning were not proven. Validated atomic download/cache checks fixed the class.
- A test added below a stage never exercised by its target proves nothing. Read the producer AND consumer: a release action can discard otherwise correct build output.
- A no-op edit is not proof a field is already right. Commit messages overstated SDK changes; the live field differed. Compute bytes from bytes and include Git modes in tree comparisons.
