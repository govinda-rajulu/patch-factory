## How a packet runs

1. Owner uploads `git bundle --all` of main (probe P2 does it inside the combo).
2. Assistant builds the packet on a branch whose parent tree is main's tree; `docs/review/controllers/suite.sh` (18 steps, about 20 minutes) must print SUITE OK on the exact tree.
3. `build_ctl.py` fills packet.tmpl.py from a CONFIG file; `build_combo.py` joins probe P2 and the controller into `pf-<packet>-combo-<sha8>.py`.
4. `rehearse.sh` against fake_gh.py: happy path plus rerun, each STOP (smoke fail, Validate fail, Pages fail, human or packet-file drift, prior head moved), bot drift merge, T1 findings.
5. Launcher: one line naming the exact combo file, size and sha256; new log per run.
6. Owner uploads the probe zip and the controller log folder. RESULT OK or RESULT FINDINGS = merged; RESULT STOP = rerun the same launcher after reading the cause.

## Lessons

- A store can replace the file behind a version name; pin the build number when patches depend on bytes.
- An upstream prerelease can break the patcher overnight; prefer stable channels for single-patch providers.
- Never hand over before SUITE OK on the exact bytes, however small the last change.
- A fallback that builds is published; only a failed build is never released.
