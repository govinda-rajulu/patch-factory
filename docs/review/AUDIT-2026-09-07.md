# External audit, 7 Sep 2026: what was accepted and what was refused

An outside review produced a strong prose audit and a set of patches. The prose found real
gaps. The patches were largely written against a repo that does not exist: wrong paths, a
`targets.json` treated as a dict when it is an array, fields (`max_sdk`, `patch_dirs`,
`source` on a candidate) that this repo has never had, and files (`src/obtainium/obtainium.py`,
`.github/workflows/release.yml`) that are not here. Recording the split so it is not re-litigated.

## Accepted and applied

| Finding | What was done |
|---|---|
| No checksum on downloaded tooling | `src/build/TOOLING.sha256` + `src/build/tooling.sh`. `utils.sh` fetches pup and APKEditor only through it; a byte mismatch aborts the build. Hashes were computed here, not copied from the audit. |
| `connection.sh` depends on one hardcoded asset | Now checks `api.github.com/rate_limit` for HTTP 200. The old code downloaded `patches-1.21.1.mpp`; the day upstream deletes that release, every build reports "connection not stable" and skips. |
| `resolve.sh` reads only release page 1 | `?per_page=100`. MorpheApp has 90 prereleases, so a `latest` candidate there could see zero stable releases on page one and be wrongly disqualified. |
| Friday-only cron | Daily 12:30 UTC. `poll.sh` still gates, so a no-op day costs one short job per polling target. |
| No automated action updates | `.github/dependabot.yml`, weekly, grouped into one PR. |
| Second keystore backup | **Yours to do. Not automatable and still the single largest risk in the repo.** |

## Refused, with reasons

- **Pin `morphe-desktop` by hash.** `build.sh` asks for its `latest` release deliberately; new
  provider bundles routinely need a newer patcher. A hash pin freezes the patcher and breaks
  every provider that moves ahead of it.
- **The supplied Docker digests.** The audit named `ghcr.io/crazy-max/cloudflarebypass` on port
  3128. This repo runs `ghcr.io/sarperavci/cloudflarebypassforscraping` on port 8000, which is
  what `utils.sh` `_cfb_get` talks to. The digest given for it was a hand-typed pattern, not a
  real sha256. Its replacement `action.yml` also dropped `setup-java`, so every build would have
  failed with no JDK. Digest pinning is worth doing later, from digests read off the real images.
- **Obtainium auto-commit.** There is no `src/obtainium/obtainium.py` and no `release.yml` in
  this repo. Nothing to wire.
- **Health dashboard.** Its deploy step would have overwritten `docs/index.html`, which is the
  real published page, and its generator iterates `targets.json` as a dict and reads fields that
  do not exist. A dashboard is a fine idea; that implementation is not.
- **`daily-poll.yml`.** Duplicates `ci.yml`, calls `src/build/poll.sh` (the file is
  `src/etc/poll.sh`), and its matrix references a `needs` job declared after it. Would not parse.
  The one-line cron change achieves the intent.
- **`reproducible.yml`.** Calls `./build.sh` (it is `src/build/build.sh`), assumes an APKEditor
  `strip` subcommand, and references `$HASH1` in a later step where it is out of scope.
  Reproducibility is worth having; this workflow would not run.
- **Integration test with a test keystore.** Real value, but it needs a new secret and a full
  runner per PR on a solo repo where `main` is already the test. Deferred, not rejected.
- **`manual-patch.yml` missing `fetch-depth: 0`.** True but harmless: `poll.sh` is only invoked
  from `ci.yml`, and nothing in the build path reads git history. No change made.

## Corrections to the audit's facts

- `max_patch_age_days` is **120**, not 60. The bufferk/Truecaller fuse is therefore **15 Nov 2026**, not 17 Sep.
- 15 targets, 14 enabled. Not 16.
- `targets.json` lives at `src/targets.json` and is a JSON **array**.
- `sonyliv` is disabled over patch compatibility and a server-visible `Change app name`, not
  because "APKMirror will not resolve"; that note in the file is stale.
