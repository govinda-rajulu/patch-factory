## What W15g changes

1. **Patch job** ("Patch <app>"): `contents: read`, no signing secret. The patcher writes an
   unsigned APK (`--unsigned`). Before patching, `build.sh` reads `patch --help`; without the
   literal `--unsigned` the build stops (`UNSIGNED_UNSUPPORTED`), never a signed fallback.
   `build_attempts.py` and `patch_target.py` refuse any `KEYSTORE*` variable or keystore file.
   The legacy shell helpers that put passwords on the command line (`patch`, `patch_multi`,
   `split_arch` in `utils.sh`) are refusal stubs. Identity is checked on the unsigned APK
   (`artifact_identity.py verify-unsigned`); the expected signer is the committed pin
   (`src/build/ci-signer.json`). The job seals the shadow receipt draft (the only job with the
   patcher jar, bundles and input APK) and hands `patch-output-<app>-<run>-<attempt>` on.
2. **Sign job** ("Sign <app>"): first-party code only (`src/build/sign_apk.py`). Places the
   hand-off (allowlisted files; a carried `src/targets.json` must be the checkout's bytes or the
   winning candidate's view), checks it is this run's exact file, decodes the keystore, checks its
   certificate equals the pin, signs with `apksigner` (passwords as `env:KEYSTORE_PASS` only,
   `--alignment-preserved true`, `--v4-signing-enabled false`, schemes by the patcher's own rule:
   v2 only at minimum SDK 24 and up, v1 v2 v3 below), deletes the keystore, then proves: one signer
   equal to the pin, the same schemes, every non-signature entry byte-identical and in order,
   4-byte and 16 KiB library alignment kept, `zipalign -c 4`, unchanged manifest. Prints
   `SIGNING_SPLIT_OK`. Then the release contract (no publishing).
3. **Publish job** ("Publish <app>"): `contents: write`, no key; releases only the signed, checked
   APK. The release contract refuses a legacy or unsigned report.
4. Receipts, qualified baselines and the status page read the three-job layout; older receipts
   and proofs still verify.

Why the rule, not apksigner's defaults: current build-tools add v3 and a v4 `.idsig` by default and
realign libraries; the Morphe Patcher 2.x signer (official source, read 31 Oct) signs v2 only at
minimum SDK 24 and up. Current releases confirm it: v2 only, except ES File and Hotstar (v1 v2 v3).

## Operating notes

- **After a failed build use "Re-run all jobs", not "Re-run failed jobs".** Hand-offs and the
  build suffix are bound to one run attempt; a partial re-run cannot reuse another attempt's APK
  and stops cleanly at the download step (the status page says so).
- The keystore alias is on the keytool and apksigner command lines (neither tool takes it any
  other way); GitHub masks it in logs. Passwords go by environment only.
- Review rounds: five scoped reviewers (signing script, workflow, receipts, patch side, hand-off),
  a re-rate and cross-file round, and a Patch to Sign to Publish chain rehearsal (9 of 9). Fixed
  before handover: Publish asked for a permission Batch Patch does not grant (every batch would
  have failed at start); the keep-going flag was not carried to Sign and Publish; a fallback or
  override build's pinned `src/targets.json` would have been refused.

## First live smoke (31 Oct, wrong call 120)

- 17 smokes on packet/w15g (PR #283): every patch job wrote the unsigned APK (`--unsigned` found
  in all 17), every Sign job read the keystore, matched the pin and signed with build-tools
  37.0.0. 4 passed the proof (adguard, edge, primevideo v2; esfile v1+v2+v3). 13 stopped at
  "signing added or removed a non-signature entry"; nothing merged.
- Cause (wrong call 120): the byte compare assumed the signer keeps every non-signature entry.
  apksig, also behind Morphe's own signer, never writes ZIP directory entries or the root
  `stamp-cert-sha256` source-stamp file. 12 hand-offs had the stamp file, mxplayer and Instagram
  had directory entries. The fixtures had neither, so tests and rehearsals passed.
- Fix (wip 9): those two kinds may disappear when signed and must never appear; everything else
  is compared as before. Errors now name the entries. The 13 real entry lists replayed: 13 of 13
  pass (0 of 13 before). Test and chain fake signers now drop them like apksig.
- Lesson: fake tools copy the real tool's output policy, from its source, not a guess; fixtures
  carry what real store APKs carry (stamp file, directory entries).

## Limits

- Same-run evidence, not isolation from a compromised runner; a malicious provider can still ship
  a malicious APK (the scan smoke and owner review remain the guard). What changes: provider code
  never runs where the release key or a write token is.
- The shadow effective key changes once (the patch command now carries `--unsigned`); the first
  build of each app reads as changed in shadow mode only.
